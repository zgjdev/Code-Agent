# CodeAgent 开发文档 01-06 修订设计

日期：2026-09-10
范围：`docs/dev/01-react-agent.md` ~ `docs/dev/06-memory-context.md`（共 6 篇）

## 1. 背景与问题

这 6 篇文档用于面试准备，对应简历中的 6 条项目描述。经 3 个并行审计（逐篇对照 `src/main/java/com/codeagent/` 源码）确认：

- **文档结构已经完整**（每篇 20+ 节，含 mermaid 架构图、时序图、调用链、面试题、简历映射），问题不是篇幅不足。
- **A 类：事实错误约 20 处** —— 文档描述的行为与代码不符，面试被追问会翻车。
- **B 类：关键细节缺失** —— 重要分支、回退路径、常量、公式、schema 未覆盖。
- **C 类：全文零 `file:line` 引用** —— 6 篇中 `file:line` 出现次数均为 0，任何一句话都无法追溯到源码。

## 2. 已确认的决策

| 决策项 | 结论 |
|---|---|
| 事实口径 | **两者都写**：设计意图 + 实际实现差异对照 |
| 细节手段 | 补充「为什么这么设计」的取舍对比（备选方案 / 为什么没选 / 代价） |
| 改动范围 | 6 篇统一修订 |
| 编辑方式 | **6 篇重排为统一骨架** |
| 「实际」栏粒度 | 只讲行为差异，不点名具体常量数值 |
| 源码位置引用 | **加 `file:line`**，读者顺行号自行核对数值 |
| 例外 | **简历中出现的关键数字补上具体值**：4 路并行、最多 2 次重试、50% 阈值、200k→167k 触发 |

数字例外的理由：这些数字直接写在简历里，面试必被问，必须能当场答出。

## 4. 各篇具体改动

### 01-react-agent.md

第 4 节新增差异：
- Token 预算默认形同不限，仅 `-Dcodeagent.react.token.budget` 生效 → `AgentBudget.java:75-80`
- **不存在**「连续异常」计数器；单次 `IOException` 直接返回

正文修正：
- 删除 §15.3「遇到登录页 / 权限不足 / 用户要求登录态才连共享 Chrome」—— 源码中无此启发式

补充缺失行为：
- `lateReasoning`：content 开始后才到达的 reasoning 缓冲为「补充思考」
- 命令输出截断与读取超时
- 工具结果写入短期记忆时的截断
- 单次调用内联执行 vs 批量走线程池

### 02-dag-orchestration.md

第 4 节新增差异：
- 节点提示词**不含**「当前计划摘要」（仅 goal + 任务描述 + 依赖结果）
- 依赖缺失是**静默丢弃**导致任务立刻可执行，不是「无法推进」
- 迭代耗尽时返回**成功**（拼接 `allResults`），不是失败
- `replan` 输入**不含**失败任务列表

正文修正：
- 状态机图：`TaskStatus` **无** `CANCELLED`；`markSkipped()` 定义但从未调用；`PlanStatus.CANCELLED` 从未赋值

补充缺失行为：
- 50% 判定位于批次内循环，可能在兄弟任务标记前触发
- `buildFinalResult` 只取叶子任务
- 单任务直接流式输出，多任务才缓冲

### 03-multi-agent-collaboration.md

第 4 节新增差异：
- Reviewer 解析失败回退到**硬编码字符串**，不是「保留原始内容作为反馈」
- 重试期间审查失败时代码**直接置 `approved = true`** 并打印「重试后审查通过」，与文档「不宣称通过」矛盾
- 重试 `while` 循环内**没有**取消检查

补充缺失行为：
- `SubAgent` 行为整体缺失：预算退出、LSP 诊断注入、仅 WORKER 使用工具、图像裁剪
- 串行 worker 的轮转选择
- `id` 为空导致的映射冲突
- 未知依赖使步骤**永久 PENDING**

### 04-code-rag-graph.md

正文修正：
- 类块实际为 **6 行**，不是 5 行
- 整文件块 `startLine/endLine` 硬编码为 0
- 「双路命中」在**任意重复 key** 都会加分（含两次语义命中）

补充缺失行为：
- 混合检索各档权重（只写存在性与位置 + `file:line`）
- `code_chunks` / `code_relations` 两张表的 schema（位置 + `file:line`）
- `cosineSimilarity` 的维度与零向量保护
- 文件扩展名白名单
- `split` 块命名规则

### 05-runtime-api-tasks.md

正文修正：
- 未匹配路径在缺 key 时返回 **401 而非 404**（`authorized()` 在路由之前执行）
- §5.4 关于「共享可变 conversation history 的 Agent」是**假设性**警告 —— `runHeadlessTask` 每次新建 Agent

第 4 节新增差异：
- worker 在 `claimNext` / `wait` 中被 interrupt 会**永久死亡、线程池萎缩**（文档只描述 runner 被中断路径）

补充缺失行为：
- `recoverRunningTasks` 只重写 `status/updated_at`，其余字段保持陈旧
- `duration_ms` 用 worker 本地时钟，取消排队任务时可能为 0
- `TaskStatus.from` 同时兼容 `value` 与枚举名

### 06-memory-context.md

正文修正：
- §14 表格中 `agentTokenBudget` **算出来但从未被使用**，纯展示用途

补充缺失行为：
- CJK 判定范围
- `contentParts` 非空时 `content` 被完全忽略
- `ContextCompressor.extractFacts` 的完整过滤管线（现文档只说「该方法未使用」）
- `LongTermMemory` 缺 `tokenCount` 时回退估算
- `setMaxTokens` 收缩时触发淘汰
- `applyContextProfile` 重置用量统计
- CODEAGENT.md 截断的保留长度
